# 폴더에서 실제 CLI 작업하기

PC 서비스(`npm run server:start`)에서 폴더를 열고 **작업하기 → Claude로 작업 / Codex로 작업**을 선택한다. 브라우저의 터미널은 실제 로컬 PTY다. 키보드 입력, CLI 확인 질문, 화면 크기 변경을 지원한다. 도구의 일반 로그인과 실행 승인 설정은 유지된다.

한 번에 하나의 CLI만 실행한다. 작업 대화는 앱이 5초마다 자동 저장한다. AI에게 별도로 저장을 요청할 필요가 없다. **작업 종료**를 누르면 CLI 종료 후 마지막 기록도 수집하며, 다른 도구가 같은 폴더의 기록을 읽고 이어받는다. 작업 결과·결정·남은 일을 대화에 명확히 남기면 날짜별 타임라인에서 확인하기 쉽다. 페이지를 이동하거나 새로고침해도 서버가 살아 있으면 같은 폴더에서 재연결할 수 있다. 서버 재시작은 실행 중인 CLI를 종료한다. 종료된 CLI 출력은 작업 종료 전까지 확인할 수 있다.

## 이 PC에서 처음 설정

1. 이 PC의 운영체제 사용자로 Claude/Codex CLI를 설치하고 로그인한다. 표준 PATH와 `~/.local/bin`, `~/.npm-global/bin`을 사용한다.
2. 서비스에 자신의 계정을 만든다.
3. PC 터미널에서 `node scripts/configure-terminal.mjs 사용자이름`을 실행한다.
4. `systemctl --user restart agent-passport`로 서비스를 재시작한다.

이 설정은 로컬 설정 파일의 `terminalOwner`만 변경한다. 웹 회원가입이나 공유 초대로 PC 실행 권한을 얻을 수 없다. 로컬 서비스와 설정된 계정에서만 실행할 수 있으며, 일반 배포 서버와 다른 사람의 PC 실행은 아직 지원하지 않는다.

## 폴더와 기억 연결

계정의 기존 프로젝트 바인딩이 있으면 실제 프로젝트 디렉터리에서 실행한다. 연결이 없으면 `.data/terminal/<account>/<folder>/workspace`에 작업 공간을 만든다. 이 작업 공간에 프로젝트 소스가 자동 복사되는 것은 아니다. 기존 바인딩 경로가 사라졌으면 잘못된 위치에서 시작하지 않고 오류를 표시한다.

각 폴더/도구마다 별도 MCP 연결 키를 로컬 파일(권한 600)에 저장하고 선택한 폴더에 읽기/쓰기 권한을 부여한다. 키를 브라우저, 프로세스 인자, 로그에 전달하지 않는다. CLI는 선택한 폴더 ID의 `get_folder_context`와 `get_folder_tasks`를 먼저 읽도록 시작한다. MCP의 기본 컨텍스트도 해당 폴더를 사용한다. 원본 기록은 신뢰되지 않은 참고 자료로 취급한다.

터미널은 PC 사용자의 실제 파일 접근 권한을 가진다. 웹소켓 연결은 로컬 접속, Host/Origin, 로그인 계정과 폴더 접근을 검증하고 연결 중에도 권한을 재확인한다. 연결 키와 터미널 데이터는 Git에 포함하지 않는다. 터미널 출력은 서버 메모리에 최근 200,000자만 보관한다.

## 검증

`node --test scripts/test-work-terminal.mjs scripts/test-client-connection.mjs`는 계정/출처 차단, 폴더 컨텍스트 전달, 중복 실행 차단, 웹소켓 입출력 및 종료/재시작, 도구별 키 분리를 검사한다. `npm run verify:local`에도 포함되어 있다. 실제 PC GUI 검증은 설치·로그인된 CLI를 별도로 사용한다.

## 대화 자동 저장

- 적용 범위는 **이 앱의 작업하기로 새로 시작한 세션**이다. 과거 대화나 일반 터미널에서 별도로 실행한 세션은 자동 업로드하지 않는다.
- 시작할 때 임의 세션 식별자를 발급한다. Claude는 `--session-id`도 지정한다. 두 도구 모두 첫 사용자 프롬프트의 정확한 식별자와 작업 디렉터리가 일치하는 JSONL만 연결한다. 다른 세션·서브에이전트 기록은 수집하지 않는다.
- 사용자/어시스턴트의 텍스트만 기록한다. 시스템 주입 내용, 실행 결과·도구 입력, 사고 과정, 이미지 데이터는 제외한다. 알려진 자격 증명 패턴은 마스킹하며, 임의의 모든 민감정보를 판별하는 기능은 아니다.
- 날짜/발화자를 보존한 기록을 선택한 폴더에 승인 완료 상태로 저장한다. 공유 폴더라면 기존 읽기 권한을 가진 참여자와 에이전트가 읽는다. 기존 타임라인이 요청·작업 보고·결정·다음 작업을 원문 기반 규칙으로 정리한다. 별도 AI 종합요약이나 실제 작업 성공의 독립 검증은 아니다.
- `.data/auto-memory/<owner>/<session>.json`에 커서·중복 방지 키·마스킹된 대기 기록을 600 권한으로 원자적 저장한다. 서버 성공 응답을 받은 기록만 대기열에서 제거한다. 서버가 저장한 뒤 응답이 유실되어도 동일 sourceKey로 재시도하여 중복을 만들지 않는다. 로그인 쿠키/연결 키는 이 파일에 저장하지 않는다.
- 실패·로그인 만료·권한 철회·용량 초과는 화면에 표시하고 로컬 대기 기록을 유지한다. 권한을 우회하지 않는다. 서버 재시작 후에는 설정된 계정이 앱에 다시 접속하면 대기 기록을 재전송한다. 저장 대기분이 있는 폴더는 전송 완료 후 다음 CLI를 시작한다.
- 화면의 자동 저장 상태와 마지막 저장 시각을 확인할 수 있다. 저장 시 타임라인도 다시 불러온다. CLI가 아직 JSONL에 쓰지 않은 토큰이나 저장하지 않은 사고 과정은 복구 대상이 아니다. 기록을 못 찾거나 손상된 줄이 있으면 그 사실을 표시한다.

검증: `node --test scripts/test-auto-memory.mjs`에서 세션 격리, 비대화/비밀 패턴 제외, 부분 UTF-8/줄 처리, 긴 메시지 분할, 응답 유실/재시작 복구, 중복 방지, 종료 직전 기록을 검사한다. Codex의 로컬 기록 설정은 [공식 고급 설정 문서](https://learn.chatgpt.com/docs/config-file/config-advanced)를 참고하되, 수집 형식은 설치된 CLI의 실제 JSONL로도 검증한다.
