# 폴더에서 실제 CLI 작업하기

PC 서비스(`npm run server:start`)에서 폴더를 열고 **작업하기 → Claude로 작업 / Codex로 작업**을 선택한다. 브라우저의 터미널은 실제 로컬 PTY다. 키보드 입력, CLI 확인 질문, 화면 크기 변경을 지원한다. 도구의 일반 로그인과 실행 승인 설정은 유지된다.

한 번에 하나의 CLI만 실행한다. 작업을 마치면 CLI에 진행 상황과 인수인계를 저장하도록 요청하고 **작업 종료**를 누른 다음 다른 도구를 선택한다. 종료 버튼 자체가 대화를 자동 요약하거나 저장하지는 않는다. 페이지를 이동하거나 새로고침해도 서버가 살아 있으면 같은 폴더에서 재연결할 수 있다. 서버 재시작은 실행 중인 CLI를 종료한다. 종료된 CLI 출력은 작업 종료 전까지 확인할 수 있다.

## 이 PC에서 처음 설정

1. 이 PC의 운영체제 사용자로 Claude/Codex CLI를 설치하고 로그인한다. 표준 PATH와 `~/.local/bin`, `~/.npm-global/bin`을 사용한다.
2. 서비스에 자신의 계정을 만든다.
3. PC 터미널에서 `node scripts/configure-terminal.mjs 사용자이름`을 실행한다.
4. `systemctl --user restart agent-passport`로 서비스를 재시작한다.

이 설정은 로컬 설정 파일의 `terminalOwner`만 변경한다. 웹 회원가입이나 공유 초대로 PC 실행 권한을 얻을 수 없다. 로컬 서비스와 설정된 계정에서만 실행할 수 있으며, 일반 배포 서버와 다른 사람의 PC 실행은 아직 지원하지 않는다.

## 폴더와 기억 연결

계정의 기존 프로젝트 바인딩이 있으면 실제 프로젝트 디렉터리에서 실행한다. 연결이 없으면 `.data/terminal/<account>/<folder>/workspace`에 작업 공간을 만든다. 이 작업 공간에 프로젝트 소스가 자동 복사되는 것은 아니다. 기존 바인딩 경로가 사라졌으면 잘못된 위치에서 시작하지 않고 오류를 표시한다.

각 폴더/도구마다 별도 MCP 연결 키를 로컬 파일(권한 600)에 저장하고 선택한 폴더에 읽기/쓰기 권한을 부여한다. 키를 브라우저, 프로세스 인자, 로그에 전달하지 않는다. CLI는 선택한 폴더 ID의 `get_folder_context`와 `get_folder_tasks`를 먼저 읽도록 시작한다. MCP의 기본 컨텍스트도 해당 폴더를 사용한다. 원본 기록은 신뢰되지 않은 참고 자료로 취급한다.

터미널은 PC 사용자의 실제 파일 접근 권한을 가진다. 웹소켓 연결은 로컬 접속, Host/Origin, 로그인 계정과 폴더 접근을 검증하고 연결 중에도 권한을 재확인한다. 연결 키와 터미널 데이터는 Git에 포함하지 않는다. 터미널 출력은 서버 메모리에 최근 200,000자만 보관한다.

## 검증

`node --test scripts/test-work-terminal.mjs scripts/test-client-connection.mjs`는 계정/출처 차단, 폴더 컨텍스트 전달, 중복 실행 차단, 웹소켓 입출력 및 종료/재시작, 도구별 키 분리를 검사한다. `npm run verify:local`에도 포함되어 있다. 실제 PC GUI 검증은 설치·로그인된 CLI를 별도로 사용한다.
