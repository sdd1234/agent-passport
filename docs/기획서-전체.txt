1. 대회 적합성 및 프로젝트 포지셔닝

의 1 차 서면 평가는 참신성 30%, 기술성 30%, 실용성 20%, 사업성 20%이며 블록체인 사용이 
필수 요건이다. 본 프로젝트는 AI 메모리와 사용자 동의·소유권을 분리해, AI 와 블록체인이 각각 필요한 역할을 갖

평가 항목
Agent Passport 대응 논리
참신성 30%

전환. 다중 Agent 시대의 실제 마찰을 직접 해결.

프로젝트 포지셔닝
“AI 를 하나 더 만드는 서비스”가 아니라, 여러 AI 사이에서 사용자의 기억·권한·동의를 이동시키는 중립 인프라. 모델 공급자가 바뀌어
도 사용자 컨텍스트는 사용자에게 남는다.
1.1 왜 블록체인이 필요한가

기억 원문 저장을 위한 블록체인이 아니다. 원문 저장은 비용·개인정보·삭제권 측면에서 부적절하다.

중앙 사업자가 임의로 바꾸기 어려운 “권한 부여/철회/만료 이력”과 “누가 소유자인지”를 검증하는 레이어로 사용한다.

공개 체인에는 scope 이름 대신 hash 또는 비식별 identifier 를 사용하여 민감 카테고리 노출을 최소화한다.

메모리 버전의 hash 를 주기적으로 앵커링하면 오프체인 원문을 공개하지 않고도 해당 버전이 사후 변조되지 않았음을 검증할 수 있다.
1.2 프로젝트가 하지 않는 것

기존 ChatGPT/Claude 앱 내부의 비공개 메모리를 무단으로 추출하지 않는다.

모든 대화를 자동으로 영구 저장하지 않는다. 장기적으로 가치 있는 기억만 추출한다.

AI 가 “진실”을 판정한다고 주장하지 않는다. 기억의 출처·버전·충돌 상태를 관리한다.

개인정보나 대화 원문을 퍼블릭 블록체인에 기록하지 않는다.

2. 문제 정의와 제품 목표
2.1 사용자 문제
한 사용자가 ChatGPT, Claude, Codex, Cursor/IDE Agent 등을 병행할 때 각 도구가 알고 있는 정보가 서로 다르다. 결과적으로 사용자는 
같은 프로젝트 구조, 선호, 결정, 진행상황을 반복해서 설명해야 하며, 오래된 Agent 가 과거 정보를 정답처럼 사용하는 “기억 충돌”도 발생한
다.

2.2 제품 목표
1.
AI 공급자와 무관한 하나의 사용자 Memory Namespace 를 제공한다.
2.
Agent 가 필요한 기억만 최소 권한으로 조회하도록 한다.
3.
대화/작업 이벤트에서 장기 기억을 구조화해 자동 추출한다.
4.
중복·충돌·오래된 기억을 Canonical Memory 로 정리한다.
5.
사용자가 언제든 Agent 별 권한을 철회하고, 철회가 즉시 검색에 반영되게 한다.
6.
MVP 단계에서 최소 2 개 AI 공급자 간 실제 기억 handoff 를 시연한다.

4.2 7 주 동안 하지 말아야 할 과개발

DID/VC 전체 표준을 처음부터 구현하지 않는다. MVP identity 는 Wallet address 로 충분하다.

모든 Agent 를 연동하지 않는다. OpenAI + Claude 2 개를 완성하고 MCP adapter 구조만 확장 가능하게 만든다.

온체인에 매 Memory write 마다 트랜잭션을 보내지 않는다. Permission event 는 즉시, memory hash 는 배치 앵커링한다.

완전 자동 conflict resolution 을 주장하지 않는다. 높은 신뢰도는 자동, 애매한 경우 사용자 확인으로 폴백한다.

복잡한 Knowledge Graph 는 후순위. PostgreSQL + pgvector 로 E2E 완성도를 우선한다.

8.4 왜 중앙 DB 권한만으로 끝내지 않는가

서비스 사업자가 DB 의 permission 값을 임의 수정해도 사용자가 검증하기 어렵다. 온체인 event/state 는 외부에서도 검증 가능하다.

여러 Agent provider 가 동일한 registry 를 기준으로 접근 정책을 해석할 수 있어 provider-independent trust anchor 가 된다.

grant/revoke 를 Wallet 이 직접 서명하므로 “사용자가 승인했다”는 provenance 가 명확해진다.

단, 성능 때문에 모든 조회마다 RPC 를 호출하지 않고 event sync/cache + 주기적 재검증을 사용한다.
8.5 Privacy-preserving anchor
Memory 마다 tx 를 만들면 비용과 프라이버시 메타데이터가 커진다. 따라서 일정 시간 동안 변경된 memory version hash 를 Merkle 
Tree 로 묶어 root 하나만 앵커링하는 구조를 권장한다.
leaf = keccak256(
  memory_id || version || content_hash || owner_salt
)
batch_root = MerkleRoot(leaf_1 ... leaf_n)

15.2 예상 질문과 답변
Q. 그냥 중앙 DB 쓰면 되는 것 아닌가?
실제 memory 저장은 DB 가 맞다. 블록체인은 데이터베이스 대체재가 아니라 provider-independent consent/ownership/audit 
trust anchor 다. 사용자 지갑이 grant/revoke 를 직접 서명하고 외부에서도 상태를 검증할 수 있다는 점이 차이다.
Q. 기존 ChatGPT 메모리는 어떻게 가져오나?
무단 접근하지 않는다. MVP 는 연결된 Agent 가 앞으로 공통 Memory Layer 를 읽고 쓰는 구조다. 이후 각 서비스가 제공하는 
export/API 범위 안에서 importer 를 추가한다.
Q. 개인정보를 퍼블릭 체인에 올리는가?
아니다. 원문·embedding·scope 이름은 오프체인이다. 체인에는 비식별 hash, permission, expiry, batch root 수준만 기록한다.
Q. AI 가 잘못된 기억을 저장하면?
source/시간/confidence 를 저장하고, 중요한/민감한 기억은 사용자 승인, 충돌은 versioning 과 Conflict Inbox 로 해결한다.
Q. Agent 가 권한 없이 직접 DB 를 호출하면?
DB 는 외부에 노출하지 않고 모든 retrieval 은 서버 PermissionService 를 통과한다. MCP tool 자체가 server-side authorization 을 
강제한다.
Q. 블록체인 RPC 가 느리면 대화가 느려지지 않나?
contract event 를 backend cache 에 동기화하고 짧은 TTL 로 사용한다. revoke 이벤트는 즉시 invalidate 하고, 민감 scope 는 필요
시 strong check 를 적용한다.
Q. 사용자가 지갑을 잃어버리면?
MVP 범위 밖이지만 production 에서는 account abstraction/social recovery 또는 enterprise recovery policy 를 고려한다. MVP
는 test wallet 로 제한한다.

부록 B. 심사 제출용 1 페이지 요약문
프로젝트명: Agent Passport - AI Agent 간 사용자 기억·권한 통합 레이어
문제
사용자는 ChatGPT, Claude, Codex 등 여러 AI 를 동시에 사용하지만 각 AI 가 보유한 맥락이 서로 달라 같은 프로젝트·선호·결정을 반복 
설명해야 한다. 또한 한 AI 에 제공한 민감정보가 다른 AI 에도 자동으로 필요한 것은 아니다.
해결
Agent Passport 는 AI 공급자와 독립된 사용자 소유 Shared Memory Layer 다. 연결된 Agent 는 MCP 를 통해 사용자가 허용한 scope 의 
기억만 검색/저장한다. LLM 이 장기 기억을 구조화해 추출하고, pgvector RAG 가 관련 기억을 검색하며, 버전 관리와 Conflict Resolver 가 
오래된 결정과 최신 결정을 구분한다.

블록체인
실제 대화와 기억은 암호화 가능한 오프체인 DB 에 저장한다. EVM 스마트컨트랙트에는 Wallet owner 가 특정 Agent 에 특정 scopeHash
의 READ/WRITE 권한을 부여·철회한 상태와 만료시간, 선택적 memory batch Merkle root 만 기록한다. 즉 블록체인은 데이터 저장소가 
아니라 사용자 동의·소유권·무결성의 독립 검증 레이어다.
MVP
GPT Agent 에서 저장한 프로젝트 결정을 완전히 새로운 Claude Agent 가 공통 Memory 에서 검색해 이어서 답변한다. 이후 사용자가 
Claude 의 development 권한을 revoke 하면 같은 질문에 접근이 차단되고, 재승인하면 다시 조회된다. 마지막으로 과거 기술 스택과 최신 
기술 스택의 충돌을 current/superseded 버전으로 시연한다.
차별성
기존 개인화 메모리가 단일 서비스에 종속되는 것과 달리, Agent Passport 는 여러 AI 가 공유하는 provider-independent context layer
이며, vector search 뿐 아니라 provenance·version·conflict·scope permission 을 하나의 구조로 관리한다.
