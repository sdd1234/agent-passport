# 프로젝트 기억 공유 서비스 사용법

## 1. 계정과 첫 프로젝트

`bash scripts/setup.sh` → `npm run dev` → `http://localhost:5173`을 엽니다. **회원가입**으로 개별 계정을 만드세요. 사용자 이름은 영문/숫자/`_.-` 3~64자, 비밀번호는 12자 이상입니다. 한 번 표시되는 복구 코드를 안전한 곳에 보관하세요. 현재 계정 복구는 이 코드로 하며 이메일 발송 기능은 없습니다.

**프로젝트 · 인수인계**에서 폴더를 만듭니다. 실제 프로젝트 경로를 입력하면 내 계정의 작업 경로와 연결됩니다. 하위 폴더도 만들 수 있습니다. 논리 폴더를 이동해도 WSL의 실제 파일은 이동하지 않습니다.

`데모 시작하기`는 공통 예시 계정입니다. 다른 사람과 실제로 공유할 때는 각자의 계정으로 가입해야 합니다. 운영 구성은 데모 로그인을 비활성화합니다.

## 2. WSL 기억을 가져오고 분류하기

설치한 저장소의 WSL 터미널에서:

```bash
npm run memory:export -- --output ~/passport-import.json --project /home/me/my-project
# 대화의 user/assistant 텍스트도 포함하려면:
npm run memory:export -- --output ~/passport-import-sessions.json --project /home/me/my-project --include-sessions
```

`--project`는 여러 번 지정할 수 있습니다. 기본 경로는 `$CODEX_HOME` 또는 `~/.codex`, `$CLAUDE_CONFIG_DIR` 또는 `~/.claude`입니다. 지원 입력:

- Codex `memories/`의 Markdown, `sessions/` JSONL의 프로젝트 메타데이터 및 선택한 user/assistant 텍스트.
- Claude `projects/*/memory/` Markdown, 프로젝트 JSONL의 작업 경로 및 선택한 user/assistant 텍스트.
- 명시한 프로젝트 최상위 `MEMORY.md`, `AGENTS.md`, `CLAUDE.md`.

자격증명·설정·도구 결과·시스템 프롬프트·추론 기록은 수집 대상이 아닙니다. 심볼릭 링크를 따라가지 않습니다. 출력은 권한 600인 로컬 JSON이며 **자동 업로드하지 않습니다**. 이미 있는 출력 파일은 덮어쓰지 않습니다. 큰 파일/세션에는 크기 제한이 있으며, 지원하지 않는 저장 형식을 임의로 추측하지 않습니다. 자동 비밀정보 제거는 완전하지 않으므로 선택한 내용은 직접 확인하세요.

GUI **기존 기억 가져오기**에서 JSON 또는 Markdown 파일을 선택합니다. 프로젝트별 분류 제안을 확인하고, 필요한 항목을 선택해 **선택 항목의 프로젝트별 폴더 만들기**를 누르거나 기존 대상 폴더를 지정합니다. 분류가 없는 항목은 프로젝트 이름을 직접 입력할 수 있습니다. 제목·내용을 수정한 뒤 **검토한 항목 서버에 저장**을 누르세요.

저장 후에는 검토 대기 상태입니다. 폴더에서 **기억 승인**을 눌러야 에이전트가 읽을 수 있습니다. 동일한 출처 키로 재시도해도 중복 생성하지 않습니다. 일부 저장 후 실패한 경우 미완료 항목만 다시 선택해 재시도할 수 있습니다. 이 도구는 지속적인 자동 감시/동기화가 아니라 명시적인 가져오기입니다.

## 3. GUI에서 정리하기

- 폴더 이름·로컬 경로·인수인계 문서 수정, 하위 폴더 생성, 폴더 이동/삭제.
- 기억 검색·편집·종류 지정·버전 이력 확인·폴더 간 이동/삭제.
- 기존 Passport 기억을 새 폴더의 검토 대기 항목으로 복사.
- 폴더 JSON 내보내기, 요금제 화면에서 계정 데이터 내보내기/탈퇴.

인수인계 문서에는 배경·진행 상황·결정 근거·다음 작업·막힌 점을 정리하세요. 내용 변경은 버전으로 검사하므로 다른 사람이 먼저 수정했으면 재조회 후 변경 내용을 반영해야 합니다. 폴더의 기억을 이동하면 대상 폴더의 공유 권한이 적용됩니다. 폴더 삭제는 포함한 기억·이력·공유를 삭제하며, 하위 폴더는 먼저 이동하거나 삭제해야 합니다.

## 4. 다른 작업자에게 인수인계하기

양쪽 PC에서 같은 서버에 각자의 계정으로 로그인합니다. 소유자는 `읽기` 또는 `편집`을 선택하고 **공유 코드 발급**을 누릅니다. 받는 작업자는 **일회용 코드로 공유받기**에 받은 12자리 코드를 입력합니다. 소유자는 표시된 상대 계정 이름을 확인한 뒤 **보내는 PC 코드 확인**에 같은 코드를 입력하고 **상대 확인 후 공유 연결**을 누릅니다. 양쪽 확인이 끝나야 접근 권한이 생깁니다.

코드는 10분간 한 번만 사용할 수 있으며 취소·재발급 시 이전 대기 요청은 무효화됩니다. 코드 만료는 연결 대기에만 적용되며 완료된 공유는 별도로 철회할 때까지 유지됩니다. 이전 초대 링크와 계정 ID 직접 신규 공유는 더 이상 지원하지 않습니다. 코드 원문은 DB에 저장하지 않습니다. 서버의 시도 제한은 재시작 후에도 유지됩니다. 앱이 이메일이나 메시지를 대신 보내지는 않습니다.


- 읽기: 문서·기억·이력 조회와 내보내기.
- 편집: 문서·기억 작성/편집, 가져오기와 검토. 소유권 변경·재공유·폴더 이동/삭제는 불가.
- 소유자: 폴더 관리와 공유/철회.

공유는 지정한 폴더에만 적용되며 하위 폴더로 자동 상속되지 않습니다. 소유자의 로컬 파일 경로와 원문 출처 경로는 다른 작업자에게 표시하지 않습니다. 철회 후 새 요청은 차단되고 해당 사용자의 에이전트 허용과 경로 연결도 제거됩니다. 이미 내려받은 사본이나 읽은 내용을 회수하는 기능은 아닙니다.

## 5. Codex·Claude 연결

폴더의 **내 Codex · Claude 연결**에서:

1. 내 컴퓨터의 작업 폴더 경로를 연결합니다. 공유받은 폴더도 내 경로를 사용할 수 있습니다.
2. 에이전트 이름을 등록하고 한 번 표시되는 토큰을 보관합니다.
3. 해당 폴더에 `읽기` 또는 `읽기 + 업데이트 제안`을 허용합니다. 기본은 차단입니다.
4. 설치 저장소의 터미널에서 토큰을 화면/명령 이력에 남기지 않고 입력합니다.

```bash
read -rs PASSPORT_AGENT_TOKEN
# 토큰을 붙여넣고 Enter
export PASSPORT_AGENT_TOKEN
npm run client:setup
unset PASSPORT_AGENT_TOKEN
```

서버 URL을 입력하면 `.data/service-client.json`에 권한 600으로 보관합니다. 원격 서버는 HTTPS만 허용합니다. 기존 전역 Codex/Claude 설정은 변경하지 않습니다. 실제 프로젝트 폴더에서:

```bash
cd /home/me/my-project
node /설치경로/agent-passport/scripts/launch-client.mjs codex
# 또는
node /설치경로/agent-passport/scripts/launch-client.mjs claude
```

요청 예시:

> get_folder_context로 이 프로젝트의 기억과 인수인계를 읽고 다음 작업을 알려줘. 작업 후 진행 상황은 propose_folder_memory로 제안해 줘.

새 도구는 `get_folder_context`, `search_folder`, `propose_folder_memory`입니다. 기존 8개 기억 도구도 유지됩니다. 도구를 실제로 호출해야 하며 모든 대화가 자동 저장되지는 않습니다. 경로가 여러 개 일치하면 가장 긴 프로젝트 경로를 선택합니다. 컨텍스트는 약 24,000자 예산을 적용하며 잘린 경우 `truncated`가 true입니다. 더 필요한 기억은 검색 도구로 읽을 수 있습니다.

서버는 사용자 폴더 권한과 해당 에이전트의 폴더 권한을 모두 검사합니다. 에이전트의 쓰기는 검토 대기 제안을 만들며 자기 제안을 승인할 수 없습니다. 연결 토큰은 내 다른 프로젝트까지 자동 허용하지 않습니다.

## 6. 요금제와 데이터 보관

현재 Free/Pro 한도는 운영자가 환경변수로 정하는 개발 기본값이며 최종 판매 가격이 아닙니다. 폴더 수, 기억 수, 암호화 본문·이력·대기 제안 저장량, 폴더 공유 건수를 서버에서 계산합니다. 팀 폴더에 다른 작업자가 쓴 데이터는 폴더 소유자의 사용량에 포함됩니다. 한도 초과 쓰기는 트랜잭션 전체를 롤백합니다. 다운그레이드 후에도 읽기/내보내기/삭제가 가능합니다.

Stripe 어댑터는 HTTPS origin과 키·가격 ID·웹훅 설정이 모두 있어야 활성화됩니다. 결제 반환 URL만으로 Pro를 부여하지 않으며 공급자의 현재 구독 상태를 확인합니다. 매시간 재확인을 시도하고, 72시간 이상 검증되지 않은 유료 상태는 Free 한도로 처리합니다. 구독 관리는 공급자 포털에서 합니다. 공급자는 교체할 수 있지만 다른 공급자용 어댑터는 별도 구현이 필요합니다.

탈퇴는 내 소유 데이터·세션·에이전트·공유를 삭제합니다. 다른 사람 소유 폴더에 작성한 협업 문서와 결제 공급자에 보관된 정보는 별개입니다. 운영 DB의 삭제와 백업 보존 기간은 별개이므로 운영자는 배포 문서에 따라 백업 보존 정책을 설정해야 합니다.
